# 台灣颱風假機率觀測平台

原生 JavaScript 靜態網站，預設進入極致全息版，有活躍預報時自動循環播放時間軸，可隨時暫停或拖曳；亦可切換至莫蘭地極簡版。資料管線讀取中央氣象署（CWA）公開颱風消息及人事行政總處（DGPA）公告，依本地規則估算 22 縣市的颱風影響，選用 Gemini 產生文字摘要。本輪系統結束後自動待命，出現新系統時恢復追蹤。

機率是未經校準的模型推估，不是官方停班停課決定；雲系、風場與雨帶是視覺模擬，不是實測雷達回波。停班停課以各縣市政府正式公告為準。

## 功能與資料狀態

- 依官方消息分別顯示每顆活躍颱風的現況與未來 96 小時內可計算的路徑，時間軸可播放、拖曳或點選預報節點。官方明確預測轉為溫帶氣旋時，保留轉性前的有效預報，並在時間軸下方標示官方轉性時限與本站估算範圍。
- 地圖顯示來源提供的七級／十級風圈與路徑潛勢；缺少十級風圈時不補造半徑。
- 縣市風力與入圈判定使用該時間點的位置；雨量為模型估算的 24 小時累積量。
- 摘要依當次颱風資料產生，切換颱風會同步切換摘要。
- 官方來源明確不再列出活躍系統時，顯示「本輪追蹤已結束，等待下一個颱風」與待命開始時間，隱藏舊預報操作、縣市模型與新聞；不據此推論一般天氣或政府是否停班停課。
- CWA 連線、格式或必要資料驗證失敗時，更新命令失敗並保留上一份 JSON。畫面分別顯示資料產生時間、官方觀測時間，資料超過兩個更新週期會提示逾期。
- DGPA 以縣市公告資料列判讀；來源不可用或無法辨識時標示未知，不當作沒有公告。「已達／未達停止上班及上課標準」只描述條件，不視為已宣布停班停課。
- 手機版將氣壓、風速、半徑、移動資訊與機率圖例放在地圖外，保留完整縣市點選範圍，並提供地圖、縣市及最新消息導覽；橫向觸控螢幕也沿用手機操作尺寸。
- 追蹤期間，最新消息從中央通訊社生活 RSS 與公視新聞網 Atom 取得近 7 天颱風相關報導，每 3 小時整理，按發布或更新時間排序、去除重複並保留最多 12 則。只保存標題、來源、新聞時間與原文連結，不保存新聞全文；待命時停止抓取新聞。
- 新聞部分來源失敗時標示部分更新；全部失敗時保留仍在 7 天內的快取並標示上次成功時間，過期新聞不再顯示。沒有新聞與來源更新失敗是不同狀態。
- 追蹤頁每 5 分鐘讀取已產生的新聞 JSON（隱藏分頁暫停抓取），每分鐘重算文章期限與來源時效；也可手動重新載入。待命頁僅在可見時每 5 分鐘檢查已發布的預報 JSON，確認新系統資料後重新載入；背景分頁不持續抓取。

## 本機使用

需要 Node.js 22 與 Python 3，沒有外部 npm 套件相依。

```bash
# 離線回歸測試；不呼叫真實 API、不改寫網站資料
npm test

# 讀取官方資料，成功後以原子替換方式更新 data/typhoon-data.json
npm run update-data

# 獨立更新新聞連結至 data/news.json
npm run update-news

# 建置正式網站至 _site，替前端資源與相依模組加入一致版本號
npm run build

# 本機預覽：http://127.0.0.1:4173
npm start
```

`buildTyphoonDataset()` 只回傳資料；CLI 透過 `updateTyphoonDataset()` 比較已保存的內容，有變更才呼叫 `writeTyphoonDatasetAtomic()`。測試使用固定來源回應與暫存目錄。

## GitHub Pages 與定時更新

1. 在 **Settings → Pages → Build and deployment → Source** 選擇 **GitHub Actions**。
2. 選擇性設定 repository secret `GEMINI_API_KEY`，用於 Gemini 文字摘要。未設定或呼叫失敗時，使用本次資料產生規則摘要。
3. CWA 使用公開的 `TY_NEWS-Data.js`，不需要 `CWA_API_KEY`；目前沒有串接需要授權碼的 OpenData API。

更新 workflow 每 3 小時執行（臺灣時間 02、05、08、11、14、17、20、23 時），亦可手動觸發：

1. 執行離線測試。
2. 先檢查 CWA。仍有活躍系統時照常更新預報、DGPA 與新聞；確認無活躍系統則進入待命，不再抓 DGPA、呼叫 AI 或抓新聞。
3. 依已保存資料的 `monitoring.mode` 決定新聞是否執行。預報抓取失敗不覆蓋原資料：原本處於追蹤模式仍可獨立更新新聞，原本待命則維持新聞停用。
4. 資料內容實際改變時才提交資料，並直接呼叫共用部署 workflow 發布該 SHA。待命未改變時不寫入新時間或重複部署；僅在最後一次 repository 提交已滿 28 天時，補一筆不改檔案的排程維護提交。
5. 回報來源與部署結果。待命的新聞略過、無變更的部署略過是預期結果；來源抓取失敗、活躍期間新聞失敗，或有資料變更卻未成功部署，仍將工作標為失敗。

更新流程不依賴機器人 push 觸發另一個 workflow。部署流程也會在一般 `main`／`master` push 或手動執行時運作，只發布公開 HTML、`src/`、`data/` 與建置版本資訊。

部署前會執行 `npm run build`：HTML、樣式與整個 JavaScript 模組圖使用相同的內容版本號，避免瀏覽器把新版頁面與舊版 CSS／JS 混用。天氣或新聞資料單獨更新時不會使前端快取失效。`_site/build.json` 記錄資源版本與實際建置的 commit，方便核對正式網站。

### 追蹤、待命與自動恢復

| 模式 | 進入條件 | 更新工作 |
| --- | --- | --- |
| 追蹤中 | CWA 仍列出颱風或熱帶性低氣壓 | 更新完整預報、官方公告與新聞，資料有變更才部署 |
| 首次待命 | CWA 成功解析為 `no_active` | 發布一次待命畫面與未知模型值，清除本輪的活躍顯示 |
| 持續待命 | 已保存待命狀態，CWA 仍明確 `no_active` | 每 3 小時只檢查 CWA；不重算模型、不抓公告／新聞、不呼叫 AI、不改資料檔或重複部署 |
| 恢復追蹤 | 待命後 CWA 出現新的活躍系統 | 完整驗證後恢復預報、公告、新聞與網站呈現 |

公開資料的 `monitoring` 記錄模式、檢查間隔及 `standbySince`。待命開始時間是本輪追蹤結束的時間，不冒充每次排程的最近檢查時間；每次檢查是否成功仍以 GitHub Actions 執行紀錄為準。來源失敗或內容無法辨識，不會被視為「系統已結束」。排程保持啟用，才能在下一個系統出現時自動恢復。

GitHub 會在公開 repository 連續 60 天沒有活動後自動停用排程（[官方排程說明](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#schedule)）。為讓長期待命仍能發現下一個颱風，待命且沒有資料變更時，若距最後提交已滿 28 天，workflow 會建立 `chore: keep scheduled typhoon discovery active` 空提交。平常不提交；維護提交不改預報、新聞或時間戳，`changed` 仍為 `false`，因此不觸發部署。

待命相關測試涵蓋首次進入、重複待命不寫檔、新系統恢復、來源錯誤保留舊資料，以及新聞／部署的預期略過與失敗結果。`tests/standby-workflow.test.mjs` 直接執行 workflow 的狀態讀取、提交與結果檢查 shell，並以暫存 Git repository 與本機 bare remote 驗證維護提交不改資料、不重複提交、不要求部署；workflow 結構另以 `actionlint` 驗證。

### 轉性預報的處理

氣象署的「預測 N 小時內變性為溫帶氣旋」是正常的預報狀態，可能不再提供颱風風速、陣風與暴風半徑。它會隨預報更新進入 96、72 小時甚至更近的時段，不能只排除固定的遠期時限。

解析器只在該預報區塊出現明確且已收錄來源樣本的轉性文字，並通過時次、日期與排序驗證後，才停止該颱風的模型時間軸。`forecastCoverage` 保留轉性資訊、最後可計算時次與固定說明；轉性點不進入風雨模型或動畫插值，不補零、不沿用上一筆風速，也不影響其他颱風。若只剩現況，縣市資料仍可查詢，播放與滑桿停用。

模型只使用轉性前且必要資料完整的時次；縮短預報不代表後續沒有風雨。兩版時間軸下方的說明獨立於 AI 摘要。正常預報缺少必要欄位、標記時間矛盾、重複／倒退時次、轉性後又出現普通預報，仍會中止更新並保留原資料與原時間戳。未有來源樣本佐證的其他生命週期文字不自動當作轉性豁免。

CWA 同時列出未命名熱帶性低氣壓（如 TD34）時，以分類、標題與 `TYPHOON` 名冊交叉確認身分，不要求不存在的國際命名或颱風編號，也不略過整個系統。`cycloneKind` 區分低氣壓與颱風；既有 `hasTyphoon` 欄位仍表示畫面有活躍熱帶系統。低氣壓低風速時次未列七級風圈時，半徑保存為 `null`、`modelAvailable: false`，縣市風雨、機率及統計保持未知；後續提供完整半徑的時次才估算。這項豁免不適用於已命名颱風、較強風速或格式損壞的半徑欄位。官方「緩慢移動」「近似滯留」或低氣壓現況的成對 `-` 移動欄位保留文字與未知移速，不補成 0 km/h。真實雙系統快照與負向案例收錄於 `tests/tropical-depression.test.mjs`。

官方將十級風半徑列為 `-` 時，僅在最大風速低於十級（24.5 m/s）且七級風圈有效的情況下，沿用未列十級風圈的處理；其他缺值或較強風速下的矛盾欄位仍拒絕發布。

PR 的 `Offline Regression Checks` 僅執行離線測試及建置，不更新正式預報或部署。正式恢復仍須另查定時工作中的 forecast 結果、公開 JSON 的官方觀測／產生時間，以及前端顯示時間。

回歸測試包含實際 120 小時與 96 小時轉性資料，以及轉性點進入 6／12／24／48／72 小時、雙颱風、單點時間軸與損壞資料；避免只修某一個時限而在下次更新再度失敗。

## 動畫效能

- 地圖動畫最多約 30 fps，縣市數值與排名最多約每秒 8 次；手動拖曳、點選與播放終點仍立即同步精確值。
- 暫停後僅在選取、圖層、hover 或尺寸改變時重畫；閱讀新聞與摘要時停止看不到的畫面更新，背景分頁停止動畫工作。
- 小型或觸控畫布使用裝置原生像素密度，最高 3 倍；桌面最高 2 倍，總量仍限制在 300 萬像素內。不改變 CSS 尺寸或縣市點選座標。
- 視窗縮放、旋轉、螢幕像素密度與字型載入改變時會更新畫布；地圖文字與提示框會限制在畫布內。解析度單獨改變時不重建投影與風場粒子。
- 風場依畫布大小調整數量並批次繪製，物理步進仍依時間計算；背景光暈採靜態漸層，避免大面積動態模糊。

`scripts/benchmark_browser.js` 是選用的本機量測工具，不參與網站執行或部署。先執行 `npm start`，再透過 Playwright CLI：

```bash
npx --yes --package @playwright/cli playwright-cli --session typhoon-bench open http://127.0.0.1:4173/
npx --yes --package @playwright/cli playwright-cli --session typhoon-bench run-code --filename scripts/benchmark_browser.js
npx --yes --package @playwright/cli playwright-cli --session typhoon-bench close
```

腳本使用獨立 Chromium context，以桌面 1440×1000／DPR 2、手機 390×844／DPR 3 測量播放、暫停與閱讀新聞，每種情境觀察 6 秒。數值是同一瀏覽器的主執行緒工作時間與繪製次數，不代表實體手機的電量、溫度或 GPU 使用率。

2026-10-21 在 Chromium 155 的本機畫質調整對照（基準版本 `2182511`，相同天氣資料；兩版都已包含 30 fps 與離屏停止更新的優化）：

| 情境 | 調整前主執行緒毫秒／秒 | Retina 調整後毫秒／秒 | 調整後地圖繪製次數／秒 |
| --- | ---: | ---: | --- |
| 極致版桌面播放 | 91.1 | 94.2 | 29.3 |
| 極致版手機尺寸播放 | 82.7 | 76.1 | 29.5 |
| 極致版桌面暫停 | 0.2 | 0.1 | 0 |

手機尺寸的畫布由 281,520 提高至 1,126,080 像素，恢復 3 倍 Retina 細節。這是每個情境 6 秒的同機觀察，數值差異不代表穩定的加速或減速結論；未量測實體 iPhone 的 GPU、電量或溫度，可使用上述腳本重新比較。

## 手機操作驗證

2026-10-21 使用 WebKit 26.6 觸控瀏覽器環境驗證極致版與極簡版，包含 320、375、390、430 像素直向及 844 像素橫向；另以 Chromium 檢查桌面版型。這是瀏覽器模擬，尚未以實體 iPhone 驗收。

- 播放／暫停、極致版播放速度、全部圖層、22 縣市選單同步、區域篩選、排序與概況展開。
- 時間節點橫向捲動、預報節點選取、滑桿點按與拖曳；直／橫向地圖實際觸控選縣市及預報位置。
- 新聞重新載入、展開／收合、來源原文開新分頁、版本切換與返回；以固定回應驗證載入失敗後重試及不同預報點數。
- 原生縣市選單實際高度至少 44 像素；以逐元素放大字體 1.5 倍檢查按鈕、圖層、時間節點與資訊標題。此壓力測試不等同 iOS 系統字體設定。
